# Sprint Ceremonies

## Sprint Planning

Frequency

- Every Monday

Duration

- 1 Hour

Objectives

- Review backlog
- Select sprint backlog
- Assign tasks
- Estimate workload

---

## Daily Stand-up

Frequency

- Every Day

Duration

- 15 Minutes

Discussion

- What was completed yesterday?
- What will be done today?
- Are there any blockers?

---

## Sprint Review

Frequency

- End of Sprint

Objectives

- Demonstrate completed features
- Collect feedback
- Verify sprint goals

---

## Sprint Retrospective

Frequency

- End of Sprint

Objectives

# Definition of Done

A task is considered complete when:

- Source code has been committed.
- Code has been pushed to GitHub.
- Pull Request has been merged.
- Feature functions correctly.
- No critical bugs remain.
- Documentation has been updated.
- Code follows project coding standards.

---

# Sprint Success Criteria

The project is considered successful when:

- All planned features are implemented.
- Documentation is complete.
- Application is deployable.
- AI integration works correctly.
- External API integration functions correctly.
- Both developers complete their assigned tasks.
- Final presentation is successfully delivered.
